# 密文完整性检查防护（Ciphertext Sanity Check）

> **类型**: concept
> **创建时间**: 2026-08-05
> **最后更新**: 2026-08-05
> **来源**: [[raw/paper-ravi2024-defeating-lcc]]

## 摘要

密文完整性检查是一种低成本检测型防护措施，由 Ravi 等人 [RCDB22] 提出，通过计算输入密文系数的均值和方差来检测低熵（恶意）密文，在解封装之前即拒绝。运行时开销仅约 5%。

## 详情

### 防护原理
- 恶意密文（用于 PC/FD oracle 攻击）通常非常稀疏和偏斜，大部分系数为 0
- 合法密文是 LWE 实例，系数在 [0, q] 范围内均匀分布
- 计算密文中每个多项式 x ∈ R_q 的均值 μ(x) 和标准差 σ(x)
- 若方差过低，拒绝该密文

### 优势
- 恶意密文在进入解封装过程之前即被拒绝
- 攻击者无法观察对应泄漏
- 运行时开销仅 ≈5%
- 对 PC oracle 和 FD oracle 攻击有效

### 局限（本论文发现的弱点）
- **不防护 DF oracle 攻击**: DF oracle 已使用均匀随机密文
- **可被公钥掩码绕过**: 本文核心贡献 1a

### 公钥掩码绕过方法（本文贡献）
1. 取公钥的一行 `(a*, b*)`，其中 `b* = a*·s + e*`
2. 将攻击密文加上公钥: `(u_atk + a*, v_atk + b*)`
3. 掩码后密文看起来均匀随机，通过完整性检查
4. 解密结果: `Δ = v_atk - u_atk·s + E`，其中 `E = e* - s^T·Δu + Δv` 为小误差
5. 若误差 E 太大导致失败，换一个掩码（不同行、旋转版本、倍数）重试
6. 单次成功率 57.8%，预期 1.73 次尝试

### 反制对策讨论
- 检查密文是否接近公钥（检查 `(u-A, v-b)` 是否很小）→ 可用小倍数或旋转公钥绕过
- 更强对策需结合其他防护措施
